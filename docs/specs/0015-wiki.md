# 0015 — User docs on the GitHub wiki

- **Status**: approved (2026-10-11)
- **Owner**: tech-lead (primary session)

## Context

The user docs (`docs/*.md` and their zh-TW copies in `docs/zh-TW/`) are read on GitHub next to the source and the specs. Readers who only want to use the player should find them in the repository's wiki, which GitHub shows as a separate, navigable site. The wiki is its own git repository (`<repo>.wiki.git`) with a flat page namespace and no pull requests, tests or review.

Decided with the user (2026-10-11): the repository stays the single source. `docs/` is still where the docs are written, reviewed in PRs and checked by `crates/app/tests/docs.rs` (0008 AC17, 0010 AC17, 0013 AC7); a CI job publishes them to the wiki. The wiki is never edited by hand: anything changed there is overwritten by the next publish.

## Behaviour

### Pages

`cargo xtask wiki <out-dir>` writes the wiki into `<out-dir>`:

| Source | Wiki page | zh-TW source | zh-TW page |
|--------|-----------|--------------|------------|
| `docs/tui.md` | `TUI` | `docs/zh-TW/tui.md` | `TUI-zh-TW` |
| `docs/config.md` | `Configuration` | `docs/zh-TW/config.md` | `Configuration-zh-TW` |
| `docs/playback.md` | `Playback` | `docs/zh-TW/playback.md` | `Playback-zh-TW` |
| `docs/login.md` | `Login` | `docs/zh-TW/login.md` | `Login-zh-TW` |
| `docs/daemon.md` | `Daemon` | `docs/zh-TW/daemon.md` | `Daemon-zh-TW` |
| `docs/mpris.md` | `MPRIS` | `docs/zh-TW/mpris.md` | `MPRIS-zh-TW` |

plus `Home` and `Home-zh-TW` (a language switcher and one link per page, titled with the page's first `# ` heading) and `_Sidebar` (both languages' links). Every page's text is the source's, byte for byte, except its relative links:

- a link to another user doc (`tui.md#x`, `zh-TW/tui.md`, `../tui.md`) becomes a link to its wiki page (`TUI#x`, `TUI-zh-TW`, `TUI`), anchor kept
- a link to anything else in the repository (`specs/0004-…md`, `../specs/…`, `../examples/app.toml`, `../../examples/…`) becomes an absolute link to that file on `master` (`https://github.com/PEKKA1117/spotify-player-but-for-tidal/blob/master/…`)
- in-page anchors (`#x`) and absolute URLs are left alone

A user doc added to `docs/` without a row in the table above is an error (the command fails naming it), so a new page cannot silently miss the wiki.

### Publishing

`.github/workflows/wiki.yml` runs on every push to `master` that touches `docs/**` (and by hand, `workflow_dispatch`). It runs `cargo xtask wiki`, replaces the wiki repository's contents with the output, and pushes when something changed, with the repository's `GITHUB_TOKEN` (`contents: write`). The wiki must exist (GitHub creates its repository with the first page saved on the web); until then the job fails with git's "repository not found".

### Pointers

The places a user is sent to the docs point to the wiki: `README.md` and `README.zh-TW.md`, the `Documentation=` line and comments of the unit printed by `tidal-player daemon unit` (and that subcommand's `--help` text), and the "no passphrase" error. Specs, code comments and `CLAUDE.md` keep pointing at `docs/`, the source.

## Acceptance criteria

- **AC1**: each source in the table becomes its page, text unchanged apart from links
- **AC2**: links between user docs (English → English, English → zh-TW, zh-TW → zh-TW, zh-TW → English) become wiki page links with their anchor kept
- **AC3**: links to other repository files become absolute `blob/master` URLs, resolved against the source's directory; in-page anchors and absolute URLs are unchanged
- **AC4**: `Home`, `Home-zh-TW` and `_Sidebar` link every page, titled from its first heading
- **AC5**: a `.md` file in `docs/` or `docs/zh-TW/` that is not in the table fails the command and names the file; so does a missing source
- **AC6**: README (both languages), the daemon unit, `daemon unit --help` and the passphrase error point at the wiki
- **AC7**: the workflow publishes on push to `master` touching `docs/**`, and only commits when the output changed

## Edge cases & errors

- Link inside a code span or block (`` `tui.md` ``): only Markdown link targets (`](…)`) are rewritten
- A link target with a title (`](tui.md "x")`) or angle brackets: not used by the docs today; left unchanged if it does not parse as a plain target
- `<out-dir>` already holds files (the wiki checkout): `.md` files there are removed first, so a page dropped from the table disappears from the wiki; `.git` is kept

## Out of scope

- Publishing the specs to the wiki (they are for developers, and stay in the repository)
- Editing the wiki by hand, or syncing wiki edits back into `docs/`
- Removing `docs/` from the repository
