# 0015 — GitHub wiki 上的使用者文件

- **狀態**：implemented（2026-10-11；AC7 在合併後於 GitHub 上檢查）
- **負責人**：tech-lead（主要工作階段）

<a id="context"></a>
## 背景

使用者文件（`docs/*.md` 及其位於 `docs/zh-TW/` 的 zh-TW 版本）是在 GitHub 上與原始碼、規格並列閱讀的。只想使用播放器的讀者，應該能在儲存庫的 wiki 找到它們；GitHub 把 wiki 顯示為一個獨立、可瀏覽的網站。wiki 是它自己的 git 儲存庫（`<repo>.wiki.git`），頁面命名空間是扁平的，沒有 pull request、測試或審閱。

與使用者討論後決定（2026-10-11）：儲存庫仍是唯一的來源。文件仍然寫在 `docs/`，在 PR 中審閱，並由 `crates/app/tests/docs.rs` 檢查（0008 AC17、0010 AC17、0013 AC7）；由一個 CI 工作把它們發布到 wiki。wiki 絕不手動編輯：在那裡做的任何修改都會被下一次發布覆蓋。

<a id="behaviour"></a>
## 行為

<a id="pages"></a>
### 頁面

`cargo xtask wiki <out-dir>` 把 wiki 寫入 `<out-dir>`：

| 來源 | wiki 頁面 | zh-TW 來源 | zh-TW 頁面 |
|--------|-----------|--------------|------------|
| `docs/tui.md` | `TUI` | `docs/zh-TW/tui.md` | `TUI-zh-TW` |
| `docs/config.md` | `Configuration` | `docs/zh-TW/config.md` | `Configuration-zh-TW` |
| `docs/playback.md` | `Playback` | `docs/zh-TW/playback.md` | `Playback-zh-TW` |
| `docs/login.md` | `Login` | `docs/zh-TW/login.md` | `Login-zh-TW` |
| `docs/daemon.md` | `Daemon` | `docs/zh-TW/daemon.md` | `Daemon-zh-TW` |
| `docs/mpris.md` | `MPRIS` | `docs/zh-TW/mpris.md` | `MPRIS-zh-TW` |

另外還有 `Home` 與 `Home-zh-TW`（一個語言切換器，以及每個頁面一條連結，標題取自該頁第一個 `# ` 標題）和 `_Sidebar`（兩種語言的連結）。每個頁面的文字都與來源逐位元組相同，只有相對連結例外：

- 連到另一份使用者文件的連結（`tui.md#x`、`zh-TW/tui.md`、`../tui.md`）改為連到它的 wiki 頁面（`TUI#x`、`TUI-zh-TW`、`TUI`），保留錨點
- 連到儲存庫中其他任何東西的連結（`specs/0004-…md`、`../specs/…`、`../examples/app.toml`、`../../examples/…`）改為指向 `master` 上該檔案的絕對連結（`https://github.com/PEKKA1117/spotify-player-but-for-tidal/blob/master/…`）
- 頁內錨點（`#x`）與絕對 URL 保持不變

加入 `docs/` 但在上表中沒有對應列的使用者文件是錯誤（指令失敗並指出該檔案），因此新頁面不會悄悄漏掉 wiki。

<a id="publishing"></a>
### 發布

`.github/workflows/wiki.yml` 在每次推送到 `master` 且動到 `docs/**` 時執行（也可手動執行，`workflow_dispatch`）。它執行 `cargo xtask wiki`，以輸出取代 wiki 儲存庫的內容，並在有變動時，使用儲存庫的 `GITHUB_TOKEN`（`contents: write`）推送。wiki 必須已存在（GitHub 在網頁上儲存第一個頁面時才會建立它的儲存庫）；在那之前，這個工作會因 git 的「repository not found」而失敗。

<a id="pointers"></a>
### 指引

使用者被導向文件的地方都指向 wiki：`README.md` 與 `README.zh-TW.md`、`tidal-player daemon unit` 印出的 unit 的 `Documentation=` 行與註解（以及該子指令的 `--help` 文字），還有「no passphrase」錯誤。規格、程式碼註解與 `CLAUDE.md` 仍指向 `docs/`，也就是來源。

<a id="acceptance-criteria"></a>
## 驗收條件

- **AC1**：表中每個來源都變成它的頁面，文字除連結外不變
- **AC2**：使用者文件之間的連結（英文 → 英文、英文 → zh-TW、zh-TW → zh-TW、zh-TW → 英文）都變成 wiki 頁面連結，並保留錨點
- **AC3**：連到儲存庫其他檔案的連結，依來源所在的目錄解析後，變成絕對的 `blob/master` URL；頁內錨點與絕對 URL 不變
- **AC4**：`Home`、`Home-zh-TW` 與 `_Sidebar` 連結每個頁面，標題取自它的第一個標題
- **AC5**：`docs/` 或 `docs/zh-TW/` 中不在表內的 `.md` 檔會讓指令失敗並指出該檔案；來源缺少時也一樣
- **AC6**：README（兩種語言）、daemon 的 unit、`daemon unit --help` 與 passphrase 錯誤都指向 wiki
- **AC7**：工作流程在推送到 `master` 且動到 `docs/**` 時發布，而且只在輸出有變動時 commit

<a id="edge-cases--errors"></a>
## 邊界情況與錯誤

- 程式碼片段或程式碼區塊中的連結（`` `tui.md` ``）：只改寫 Markdown 連結目標（`](…)`）
- 帶標題的連結目標（`](tui.md "x")`）或角括號：文件目前沒有用到；若無法解析為單純的目標就保持不變
- `<out-dir>` 已有檔案（wiki 的 checkout）：先移除其中的 `.md` 檔，因此從表中拿掉的頁面會從 wiki 消失；保留 `.git`

## 測試計畫

| AC | 測試（檔案 :: 名稱） | 驗證內容 | 預期的紅燈 |
|----|---------------------|-----------------|--------------|
| AC1 | `xtask/src/wiki.rs` :: `ac1_pages_from_sources` | 由測試資料（fixture）`docs/` 樹得到的頁面名稱與文字 | 存根`build` 不回傳任何頁面 |
| AC2 | `xtask/src/wiki.rs` :: `ac2_doc_links`（表格：來源目錄 × 目標 → 改寫結果） | 帶錨點的頁面連結 | 存根`rewrite_links` 原樣回傳輸入 |
| AC3 | `xtask/src/wiki.rs` :: `ac3_repo_links`（表格） | `blob/master` URL；`#x`、`https://…` 不變 | 存根`rewrite_links` 原樣回傳輸入 |
| AC4 | `xtask/src/wiki.rs` :: `ac4_home_and_sidebar` | 每個頁面每種語言各被連結一次，並附上它的標題 | 存根`build` 不回傳任何頁面 |
| AC5 | `xtask/src/wiki.rs` :: `ac5_unknown_or_missing_doc`（表格） | 指出該檔案的錯誤 | 存根`build` 回傳 `Ok` |
| AC1–AC5 | `xtask/tests/wiki.rs` :: `real_docs_build` | 對真正的 `docs/` 執行 `build` 會成功，且輸出頁面中沒有以 `.md` 結尾而非絕對的連結 | 存根`build` 不回傳任何頁面，所以頁面數量不對 |
| AC6 | `crates/app/tests/docs.rs` :: `ac6_pointers_to_wiki` | README、README.zh-TW、unit 文字與錯誤文字都含有 wiki URL，且沒有 `docs/<page>.md` | 它們仍指向 `docs/` |
| AC7 | 驗收時手動：讀工作流程檔；合併後檢查它在 `master` 上的執行與 wiki 的歷史。沒有測試：這需要 GitHub | — | — |

<a id="out-of-scope"></a>
## 不在範圍內

- 把規格發布到 wiki（規格是給開發者看的，留在儲存庫中）
- 手動編輯 wiki，或把 wiki 的修改同步回 `docs/`
- 從儲存庫移除 `docs/`
